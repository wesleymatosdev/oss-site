# oss-site — project notes

## P0 — the subdomain does not resolve (2026-09-11)

`oss.wesleymatos.dev` has **no Cloudflare DNS record at all**. Not misconfigured — absent.

```
dig +short oss.wesleymatos.dev     -> (empty)
curl https://oss.wesleymatos.dev   -> 000, could not resolve host
```

The repo, the Pages workflow, and both CNAME files are correct. Only the DNS record is
missing. For comparison, measured the same day: apex, blog, skills and demo all return 200.

Fix: add a proxied Cloudflare CNAME `oss` -> `wesleymatosdev.github.io`, mirroring how
`skills` is configured. Wesley must do this — the local wrangler OAuth token has
`zone (read)` only, no DNS write, and is authenticated as `olivine.lapdogs0h@icloud.com`.

Consequence worth knowing: `website` commit `987cfdc` added a nav linking
"Open Source" -> oss.wesleymatos.dev, so the main site has been sending visitors to a
dead host since it landed.

## collect.py bug — curated `url` is never backfilled

`collect.py` enriches curated entries' `stars` from the GitHub API when a repo name
matches (collect.py:322-327), but never backfills `url`. Because `CURATED` hardcodes
`url: None` for repos that were local-only when the table was written, **10 entries render
"local only (coming soon)" although their repos are public**:

  ollama-axi, herdr-axi, scp-axi, tmux-axi, session-rc, xcap-recorder,
  anti-babysitting-pipeline, session-categorizer, usage-dash, brainrs

All verified `private=false` via `gh api repos/wesleymatosdev/<name>`, 2026-09-11.

## Star buttons — what actually works

- **GitHub `/stargazers` pages are 404 globally** — verified on both
  `wesleymatosdev/spinning-cube` and `microsoft/vscode`. Never link that path.
- There is no separate "star intent" URL. The repo page is the star surface.
  Logged-out, clicking Star routes through `github.com/login?return_to=<repo>`.
- Chosen approach: a plain anchor to the repo styled as a nebula button, plus the
  build-time `stars` count collect.py already fetches. Zero third-party runtime requests.
- Rejected: buttons.github.io / ghbtns.com (third-party request per button; ghbtns'
  iframe has `last-modified: Dec 2022`), and client-side `api.github.com` fetches
  (60 req/hr per IP unauthenticated, adds a loading state to a static page).
- Note: skills.danicat.dev's "star" button is NOT a GitHub star — it's a Firebase
  Firestore like-counter with anonymous auth. Different thing entirely.
